        <section id="overview">
            <h2>1. Introduction to Firewalls</h2>
            <p>A firewall is a network security device that monitors and filters incoming and outgoing network traffic based on an organization's previously established security policies. At its most basic, a firewall is the barrier that sits between a secured internal network and an unsecured network, such as the Internet.</p>
            <ul>
                <li><strong>Stateless Firewalls:</strong> Inspect packets individually without tracking connection states.</li>
                <li><strong>Stateful Firewalls:</strong> Track the state of active connections and determine which network packets to allow through.</li>
                <li><strong>Next-Generation Firewalls (NGFW):</strong> Go beyond port/protocol inspection to include application awareness, integrated intrusion prevention (IPS), and cloud-delivered threat intelligence.</li>
            </ul>
        </section>

        <section id="architecture">
            <h2>2. Palo Alto Architecture & Security Zones</h2>
            <p>Palo Alto Networks firewalls utilize a zone-based architecture. Traffic cannot flow between interfaces until those interfaces are assigned to zones, and security policies are created to allow traffic between those zones.</p>
            <ul>
                <li><strong>Internal (LAN):</strong> Trusted user network segment (e.g., <code>10.1.1.0/24</code>).</li>
                <li><strong>DMZ (Demilitarized Zone):</strong> Semi-trusted zone housing publicly accessible services like web or voice servers.</li>
                <li><strong>Untrust (Internet):</strong> Unsecured external network segment.</li>
                <li><strong>Management Interface:</strong> Dedicated out-of-band management interface (e.g., <code>192.168.30.177</code>).</li>
            </ul>
        </section>

        <section id="policy">
            <h2>3. Security Policy Fundamentals</h2>
            <p>Palo Alto firewalls evaluate rules from top to bottom. The first rule that matches the traffic criteria is applied.</p>
            <ul>
                <li><strong>Intra-zone Traffic:</strong> Allowed by default (traffic within the same zone).</li>
                <li><strong>Inter-zone Traffic:</strong> Denied by default (traffic moving between different zones requires explicit allow rules).</li>
                <li><strong>App-ID & User-ID:</strong> Enables rule enforcement based on specific applications (e.g., web-browsing, DNS, SIP) rather than just IP addresses and port numbers.</li>
            </ul>
        </section>

        <section id="lab">
            <h2>4. Lab Topology Example</h2>
            <p>In a standard firewall lab environment, traffic flows from internal client machines through dedicated firewall interfaces before reaching external networks or DMZ servers:</p>
            <ul>
                <li>Client Workstation: <code>10.1.1.10</code> connected to Interface <code>eth1/1</code></li>
                <li>DMZ Server: <code>20.1.1.1</code> connected to Interface <code>eth1/2</code></li>
                <li>Egress Router / ISP: Connected to Interface <code>eth1/3</code></li>
            </ul>
